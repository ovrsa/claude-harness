# Draw.io Review Checklist

## 目的

Draw.io 上での手動確認観点を固定し、第三者に見せる前の微調整基準を揃える。

## Critical Rules チェック（最優先）

- [ ] 空きマスにプレースホルダラベル（`未関与` `主担当ではない` `結果待ち` `参照のみ`）が置かれていない（原則は空白）
- [ ] 条件分岐が独立ひし形ノード（`rhombus`）として配置されている（タスクボックス内の `◇` 文字埋め込みは NG）
- [ ] 1 ボックスに `① 〇〇 / ② 〇〇` と複数手順を並べていない（1 タスク = 1 ボックス）
- [ ] レーン内タスク間は番号なしの細い矢印で接続、レーンを跨ぐ handoff のみ番号付きラベル

## 原本の確認

- この Draw.io ファイルがスイムレーンの正本として扱われている
- 補助の Markdown や README から、この Draw.io ファイルへ辿れる
- 現状図と改善後図のページ名が見て分かる

## 軸の確認

- 横軸（列）に担当・システムが並んでいる
- 縦軸（行）に業務フェーズが並んでいる
- フェーズ名とレーン名が省略語だけになっていない
- 特別な理由がない限り、時系列が縦軸（上から下）になっている

## グリッド方式の確認

- 3層分離方式で描かれている
  - 層1: 背景塗り（全体枠 / 列ヘッダ・行ヘッダ・フェーズ行の塗り）
  - 層2: 1 px の細い区切り線（vertex として描かれている）
  - 層3: 小さなタスクボックス・独立ひし形（マス内に余白付き）
- ヘッダラベルは `text;html=1` でセル境界を持たない
- タスクボックスはマス全体を塗りつぶしていない（上下左右に 15〜25 px の余白）
- 空きマスは空白のままにしている（プレースホルダラベルを置かない）
- 例外的にボトルネック表現を入れる空白だけ、灰小ラベル（120×30 程度・`48h 待機` `承認停滞` 等）

## 矢印の確認

- 矢印は vertex（タスクボックス）間でのみ接続されている（背景塗りや区切り線を source / target にしていない）
- 矢印ラベルに `labelBackgroundColor=#ffffff` が付いている
- 主経路（青太）/ 前提（紫破線）/ 停止（赤破線）/ フェーズ間（灰点線）の使い分けが守られている

## セル・ノードの確認

- 各ボックスは 1 つの目的・1 つのアクションに絞られている（複数手順は分割済み）
- ボックス本文は 1 行（動詞句）に収まっている
- 1 ボックスに `① 〇〇 / ② 〇〇` と並べていない
- 条件分岐は独立ひし形（`rhombus`）として配置され、`◇` 文字や `判定` をタスクボックス内に埋め込んでいない
- レーンを跨ぐ handoff 矢印に番号ラベル（`① ② ③ …`）が付いている
- レーン内タスク間矢印は番号なし（順序は配置で読める）
- 空きマスはそのまま空白（プレースホルダ禁止）
- ツールやサービスを置く場合、その表現が主役を邪魔していない

## 矢印の使い分け確認

- 青太矢印はレーン跨ぎの主経路だけに使われている（番号付きラベル）
- 青細矢印はレーン内タスク間に使われている（ラベルなし）
- 紫破線は補助・前提（二重管理等）に限定されている
- 赤破線は待ち・停止・NG 差戻しに限定されている
- 矢印の折り返しが多すぎない
- 矢印が凡例や注記に重なっていない

## 比較の確認

- 現状図と改善後図で同じフェーズ粒度になっている
- 改善後図で削除・自動化・人が残す判断が読み取れる
- 現状図の課題が改善後図でどう変わるかが読める

## ツール / サービスの確認

- ツールやサービスは、セル近くの補助ボックス・行・注記のいずれかで一貫して表現されている
- Excel、メール、ATS などの道具が、どこで使われるか分かる
- ツール表現が主経路より目立っていない
- 分散管理や二重入力の原因が伝わる

## 最終確認

- 第三者が矢印だけ追って主シナリオを説明できる
- 読み手が「誰がいつ何をするか」を迷わない
- 説明文なしでも図だけで会話を始められる
