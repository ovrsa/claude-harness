# 論点整理（issue-framing）

## Overview

曖昧な発言を「決定可能な問い」に変換し、日付ではなくトリガーでロードマップを引く技法。
核心: **課題リストではなく論点（問い）リストを作る。確定していないものの上に計画を建てない。**

## When to Use

- 議事録・ヒアリングメモから「この後どう動くか」をまとめるとき
- 先方の構造化・意思決定待ちで、こちらの計画が立てにくいとき
- 使わない場面: 要件が確定済みで決定を記録するだけのとき（→ `/docs-build` で `docs/design/` に書く）

## 手順

※ この手順は1回で終わらない。先方から新情報が来るたびに 0→5 を回して更新する（マッキンゼー7ステップの反復と同じ）。

### 0. 主要問題を1文で定義する

論点を列挙する前に、プロジェクト全体の問いを1文で置く（何を・誰にとって・どうなれば解決か・いつまでに/何をトリガーに）。以降の論点はすべてこの問いの分解として位置づけ、この問いに寄与しない論点は扱わない。

例: 「経理の請求書処理を、来期予算確定をトリガーに段階自動化するために、今期中に何を確定させるべきか？」

### 1. 発言の仕分け（確定度4分類）

すべての発言・情報を4つに分類する。**曖昧語マーカー**（〜かも・まだ・いきなり・できるところから・頭の中にある・検討したことある）が付いた発言を「合意済み」に入れることを禁止する。

| 分類 | 定義 | 例 |
|---|---|---|
| 合意済み | 双方が明言した決定 | 「早くなんとかしたい」（優先着手の合意） |
| 方向性 | 意向はあるが条件未定 | 「できるところからやりたい」 |
| 未決（論点） | 決めれば動けるが決まっていない | ツール選定、例外の扱い |
| 不明 | 判断材料の情報自体がない | 件数、既存規程の有無 |

**禁止**: 緊急度・難易度・工数を未確認情報から推定して表に載せること。載せるなら「（推定・未確認）」を必ず付ける。

### 2. 論点化 — 「問い」に変換する

未決・不明の各項目を疑問文にし、3点セットを付ける:

- **問い**: 「〜すべきか？」「〜はどこにあるか？」（「例外が多い」→「例外は何パターン・何件で、機械判定の入口をどこに置くか？」）
- **ボール**: 先方 / こちら / 共同（誰が決められるか）
- **アンブロック条件**: 何が分かれば・決まれば先に進めるか

### 2.5 優先順位 — インパクト×動かせるか

各論点を2軸で評価する（マッキンゼー7ステップの優先順位付け）:

- **インパクト**: 解決したとき主要問題（手順0）にどれだけ効くか
- **動かせるか**: こちらのアクションで前進させられるか（≒ボールがこちら/共同にあるか）

**低インパクト×動かせない論点は刈る**（ボードに「保留」と明記して追わない）。最優先は高インパクト×動かせるもの。高インパクト×動かせないものは「待つ」型でトリガーだけ定義する。

### 3. アクション4型への変換

各論点をちょうど1つの型に割り当てる。質問には**どの論点をアンブロックするための質問か**を必ず紐づける。

| 型 | 使う条件 | 出力 |
|---|---|---|
| 聞く | 先方しか答えを持たない | 質問リスト（論点IDつき・優先度つき） |
| 調べる | こちらで検証可能 | 検証タスク |
| 決めて提示 | どちらでも決められる・待つ理由がない | 仮決め案＋承認依頼 |
| 待つ | 先方の内部調整が必要 | **トリガー定義**（「〜の連絡が来たら〜する」） |

### 4. Ready条件（着手条件）の明文化

「確定した」の判定を機械的にできる形で書く。例: ①項目と値域が決まっている ②例外時の挙動が決まっている ③例外の検知方法が決まっている。ドメインに合わせて3条件程度に絞る。

### 5. ロードマップ — トリガー駆動で引く

- **日付を付けてよいのは自分ボールのタスクだけ**。先方ボールにカレンダー日付・「〜1ヶ月」等の期間を書かない。
- フェーズの区切りは日付ではなく **Ready条件の充足**: 「Phase 2 は論点3・5が確定したら開始」。
- 確定度の低いテーマほど後ろへ。最初の着手は「合意済み×こちらボール×小さい」ものから。

## 出力テンプレ（論点整理ボード）

| # | 論点（問い） | 状態 | ボール | インパクト×動かせるか | アンブロック条件 | アクション型 | 次の一手 |
|---|---|---|---|---|---|---|---|

＋ 主要問題定義（1文） / 合意済み事項 / 前提・制約（確定度ラベルつき） / トリガー駆動ロードマップ / 質問リスト（論点ID紐づけ）

## Common Mistakes

| 失敗 | 直し方 |
|---|---|
| 「〜かも」を前提にロードマップを建てる | 曖昧語マーカー検出→分類1に落とさない |
| 課題リスト止まり（問いになっていない） | 疑問文＋ボール＋アンブロック条件に変換 |
| 先方ボールに日付を約束する | トリガー駆動（「確定したら着手」）に置換 |
| 緊急度・難易度を無根拠に数値化 | 未確認は「推定」ラベル or 論点（不明）へ |
| 質問リストが決定に紐づかない | 各質問に「アンブロックする論点ID」を付与 |
| 全部聞こうとする | 最初の着手をブロックしている論点の質問だけ先に |
| 問題定義なしに論点を列挙して散らかる | 手順0の1文に寄与しない論点は扱わない |
| 動かせない論点に工数をかける | インパクト×動かせるかで刈る。「待つ」はトリガー定義のみ |
