# パイプラインを実際に使われている経路に合わせる

日付: 2026-08-12

## Objective

正本文書が前提にしている手順のうち、実測で一度も起きていない経路を削るか、実際に起きている挙動に書き直す。

## なぜ今これか

前タスク（[乖離修正](./2026-08-12-lifecycle-drift-fix.md)）は「機構を名指しする記述」だけを対象にした。
残ったのは**機構を名指ししないが誰も通っていない経路**で、こちらは嘘ではないぶん見つかりにくい。
6ヶ月分の発話 3,024 件を照合したところ、`/plan-task` `/execute-plan` `/implement-task` `/review-task`
`/verify` `/eval` `/route-task` はユーザーからの入力が**0回**だった。それでも `plan.md` や
`verification-summary.md` は毎回作られている。**パーサとテンプレートが機構で、コマンドは語りだった。**

## Non-goals

- `research.md` を artifact モデルから削除すること。`/research` は6ヶ月で3回使われている
- 入力0回のコマンドの一括削除。`/verify` `/eval` `/review-task` はゲート必須成果物の担当なので別タスク
- 新しいフックの追加
- ECC 由来の `multi-*` コマンド群

## 判明した具体的な欠陥

1. **`/plan` と `/plan-task` は前後どちらにも配線が無かった。** grill 系スキルは plan に言及せず、
   `/docs-build` も plan を参照しない。`/plan` が宣言する唯一の入力は `research.md` だけで、
   その `research.md` にもパーサが無い。`/plan-task` はユーザー入力0回。
2. **`research.md` はパーサを持たない唯一の成果物だった。** 存在確認だけなので空ファイルで通る。
   2026-07-28 に「空虚に満たせるゲート」を理由に編集ブロックを撤去したのに、同じ形が別の場所に残っていた。
   内容は `docs/design/` と重複しており、生き残るのは後者。
3. **「design doc が Plan mode の入力になる」を実装するコードが無い。** design doc は決定の記録なので、
   修正タスクでは何が壊れていたかが確定する実装後にしか書けない。**入力ではなく出力。**
4. **`/worktree-start` は6ヶ月で2回しか打たれていない**（最後は 2026-02-14）。それでも
   `rules/common/worktree-policy.md` の Required Flow はユーザーがこのコマンドを打つ前提で書かれていた。
   実際の worktree はすべてエージェントが `EnterWorktree` を呼んで作っている。
5. **「`main` へのマージは PR + 必須チェック通過を前提とする」は `~/.claude` では満たせない。**
   このリポジトリに remote は無い（`git remote` が空）。PR を出す先が無い。

## 決定

| 項目 | 方向 |
|---|---|
| 1 | コマンド2本を削除。`plan.md` は `templates/plan-template.md` から直接書く |
| 2 | 必須から外す。チェーン段は `pending` -> `skipped`。存在すれば `complete` として認識は続ける |
| 3 | 文書 -> 実態。design doc は出力であると書き直す |
| 4 | **文書 -> 実態、かつ既定の挙動側に寄せる。** worktree はエージェントが作る。コマンドは上書き用に降格 |
| 5 | remote の有無でスコープする |

4 が唯一の設計判断だった。強制を戻す選択肢もあったが、2026-07-28 に撤去した強制は
`plan.md` の `worktree_required` にしか信号が無く、`.md` だけを書く作業には最初から効いていなかった。
**同じ形の強制を復活させても同じ理由で効かない。** 代わりに、忘れる余地のある「規律」から
「エージェントの既定の挙動」へ移した。フックは何も検査しないままである。

削除したものが復活しないよう、契約監査に `assertFileAbsent` を足した。既存の
`assertIncludes` / `assertExcludes` と同じく、**不在を assert する**（2026-08-11 に確立した流儀）。

## 却下した案

- **入力0回のコマンドを全部消す**: `/verify` `/eval` `/review-task` は完了ゲートが読む成果物の担当。
  入力0回でも、成果物のスキーマを説明する場所として機能している。コマンドが語りだったという結論は
  「消してよい」を意味しない
- **`research.md` にパーサを書く**: 内容が `docs/design/` と重複している。パーサを足すと
  維持義務が1つ増え、重複した契約が2箇所に置かれる
- **worktree を再度強制する**: 上記のとおり、同じ信号しか無いので同じ理由で効かない
- **`/worktree-start` を削除する**: Detached Mode・base branch 指定・slug 固定という
  既定から外れる用途が3つ残っている。降格で足りる
