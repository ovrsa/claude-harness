# タスク完了前の仕上げ

## Objective

変更したコード、文章、コメントの見直しと必要な再検証を、完了報告とチケット Done の前に行う。
修正不要でも対象と理由を残し、記録が空、未実施、変更前のものなら完了検査を通さない。

## なぜ今これか

使い方では仕上げをエージェントに任せられると説明しているが、PRI-236 の実行ログでは
Done の後に設計書と運用文書の更新漏れを認めていた。レビューの見出しだけの検査と、
既定ワークフローの verify から COMPLETE への遷移では、この抜けを検出できない。

## Non-goals

- 変更対象外の一括整理、upstream スキルの変更、全会話を止める Stop フックの追加。
- 機械による文章品質の保証、外部チケット API の操作の一律遮断。

## 触る対象

- `review-summary.md` の仕上げ記録、パーサ、完了検査 CLI とその公開入出力のテスト。
- 既定ワークフローの仕上げ・受容段階と runner の完了直前検査。手動経路も同じ検査を呼ぶ。
- `CLAUDE.md`、使い方、実装・レビュー・受容の指示、facet とテンプレート。

## 却下した案

- 注意書きの追加だけで済ませる案。既に存在する指示が抜けているため採らない。
- 見出しの追加だけで済ませる案。空欄や前のタスクの記録が残っていても通るため採らない。

## 検証

使い捨てリポジトリで CLI の終了コードと診断、runner の DONE/拒否を確認する。
空欄、修正不要の理由、変更後の古い記録、観測の要否、再検証の記録を対象とする。
実行時の検査を呼ばない手動経路は規律に依存する。この制約を使い方に明記する。
